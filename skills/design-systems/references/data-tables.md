# Плотные данные, таблицы и дашборды — reference

> Глубокий материал для `skills/design-systems`. Грузится по требованию, когда задача про таблицу, плотный список, расписание или дашборд. Кросс-ссылка из `skills/graphic-design` (визуальная плотность).
> Это ядро B2B HR Tech: посещаемость в WTM — плотные табличные данные, а месячный формат просмотра — текущий фокус HR (`team/current-projects.md`). База — Mantine Table плюс локальные компоненты WTM (графики, расписания).

## Зачем это

Таблица — не «сетка ячеек», а компонент с анатомией, паттернами и полным набором стейтов. Reference собирает паттерны плотных данных, чтобы не изобретать их каждый раз и не сваливать «просто выведи данные». Решения по компоненту (взять / расширить / создать локальный) — по методу `skills/design-systems`; здесь — что именно должно быть в таблице.

## Anatomy

- **Toolbar над таблицей:** поиск, фильтры, переключатели плотности, bulk-действия над выбранным, экспорт.
- **Заголовок (header):** имена колонок, индикатор сортировки, ресайз/закрепление колонок.
- **Тело:** строки и ячейки; выравнивание по типу данных; выделение строк (checkbox), inline-действия.
- **Футер / пагинация:** счётчик, пагинация или подгрузка, итоги по колонкам (если нужны).
- **Слой состояний:** empty, no-results, loading, error поверх тела.

## Core-паттерны

- **Сортировка.** По колонке; видимый индикатор направления; заданная сортировка по умолчанию. Не больше одной активной без явной мультисортировки.
- **Фильтры и поиск.** Где живут фильтры (toolbar / боковая панель), видимость применённых фильтров (chips), быстрый сброс. Фильтр, обнуливший выдачу, ведёт в состояние **no-results**, не в empty.
- **Пагинация vs виртуализация.** Тысячи строк (в WTM — тысячи сотрудников) нельзя рендерить разом: либо пагинация, либо виртуализация видимого окна. Выбор — по сценарию: пролистывание глазами → пагинация; непрерывный скролл больших наборов → виртуализация.
- **Sticky header и sticky первая колонка.** Для широких плотных сеток (расписание × сотрудники): шапка и колонка-идентификатор остаются на месте при скролле — иначе теряется, чья это строка.
- **Плотность строк.** Compact / comfortable как опция: B2B-пользователь часто хочет уместить больше на экран. Плотность — из шкалы токенов, не «на глаз».
- **Действия над строкой.** Inline для 1–2 частых, меню («⋯») для остального; bulk-действия появляются при выделении строк.
- **Управление колонками.** Показать/скрыть, ресайз, закрепление — для широких сеток посещаемости.

## Стейты (все восемь обязательны, специфика таблицы)

Полный набор стейтов — командный стандарт (принцип №1, `team/design-principles.md`). Для таблицы критичны и часто путаются:

- **empty** — данных ещё нет (первый вход, ничего не заведено): объясни, что это за таблица и как появятся данные.
- **no-results** — данные есть, но фильтр/поиск обнулил выдачу. Это **другое** состояние, чем empty: здесь — «ничего не найдено, сбросьте фильтр», а не «заведите первую запись». Тексты — `skills/ux-writing` (сверить с `team/brand-tone.md`).
- **loading** — skeleton-строки, а не спиннер по центру: пользователь видит форму таблицы и что данные едут (принцип «loading skeletons для ожидания ≥ 500 мс»).
- **error** — загрузка не удалась / частично: что произошло и как повторить, без «что-то пошло не так».

## Плотность и сканируемость (связка с graphic-design)

Плотный ≠ хаотичный. Визуальную сторону ведёт `skills/graphic-design` (плотность, выравнивание, ритм), здесь — что критично для таблиц:

- **Выравнивание по типу.** Числа и суммы — по правому краю, текст — по левому, чтобы столбец читался сверху вниз.
- **Разделение строк** пространством и лёгким разделителем, а не жирными рамками на каждую ячейку (границы утяжеляют).
- **Статусы — не только цветом.** Иконка/подпись рядом с цветом (обязательный a11y-стандарт).
- **Токены, не magic numbers** для ширин, отступов, плотности (принцип №3).

## Когнитивная нагрузка (связка с ux-ui-theory)

Плотная таблица давит на рабочую память. Опирайся на `frameworks/cognitive.md`:

- **Recognition over recall** — показывай данные рядом, не заставляй помнить значение из соседнего экрана/строки; sticky-колонка ровно про это.
- **Прогрессивное раскрытие** — строка показывает главное, деталь открывается по требованию (раскрытие строки, боковая панель), а не всё сразу в ячейках.
- Cognitive load снижается группировкой и чанкингом плотного набора, а не удалением нужных данных (для B2B урезание данных часто **повышает** нагрузку — пользователь идёт искать их в другом месте).

## Таблица vs дашборд

Не путай рабочую таблицу и дашборд — у них разные задачи:

- **Рабочая таблица** — оперировать данными (HR создаёт и правит графики, прикрепляет сотрудников): плотность, действия, редактирование.
- **Дашборд** — обзор и мониторинг (руководитель следит за посещаемостью команды): агрегаты, тренды, немного строк, drill-down в таблицу за деталями.
Один экран, пытающийся быть обоими сразу, обычно проваливает оба сценария.

## Адаптив и мобилка (связка с mobile)

Широкая таблица не влезает в телефон. Паттерны — `skills/product-design/references/mobile.md`:

- Reflow строки в карточку (label-значение) для узкого экрана.
- Либо горизонтальный скролл со sticky-первой-колонкой (идентификатор строки).
- Действия над строкой — тач-цели ≥ 44pt, не мелкие иконки вплотную.

## Mantine и локальные компоненты

База — Mantine Table (`team/profile.md`). Специфичные для WTM паттерны (графики, расписания, события) — локальные компоненты поверх базы, по методу `skills/design-systems`: сначала ищи в DS и Mantine, создавай локальный только если нет, документируй по `templates/component-doc.md`. Breaking change в общий табличный компонент — не solo, согласуется со всеми дизайнерами.

## Анти-паттерны

- **Рендер всех строк** без пагинации/виртуализации на тысячах записей.
- **Спиннер вместо skeleton** в loading.
- **empty и no-results слиты** в одно состояние — пользователь после фильтра видит «заведите первую запись».
- **Статус только цветом** в ячейке.
- **Границы на каждую ячейку** — визуальный шум вместо структуры пространством.
- **Magic-number ширины колонок** вне токенов.
- **Десктопная таблица на телефоне** без reflow.
- **Дашборд-таблица-всё-сразу** — обзор и работа смешаны на одном экране.
