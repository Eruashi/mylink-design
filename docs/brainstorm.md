# Брейншторм решений

Статус: черновик 2026-09-25, ждёт выбора. Причины — `docs/problem.md`.

## Идеи по причинам

### 1. Знания DS недоступны ИИ
- **1A. Выгрузка из Figma в репо.** Claude читает Tokens и Core kit (только чтение) и генерирует `ds/tokens.md` (таксономия, имена, значения) и `ds/components.md` (страница, node, статус, % Tokens; OLD-дубли помечены «не использовать»). Обновляется по команде «обнови реестр».
- **1B. Рамка «только из источника».** Любое решение ссылается на токен или компонент из реестра. Нет подходящего — не подставлять, а предложить новый и спросить.
- **1C. Иллюстрации — только «Используем».** Список из 10 используемых + правила стиля; остальной пак игнорируется.

### 2. Нет живой памяти задачи
- **2A. Карточка таски, которую ведёт Claude.** Своя версия ТЗ: текущая логика, журнал решений (дата → что изменилось → кто согласовал), отклонённые варианты. Ты пишешь «решили X» — Claude обновляет.
- **2B. Сверка с ТЗ БА.** Пришла новая версия ТЗ — Claude показывает, что расходится с карточкой.
- **2C. Status-файл DS знает, где правка.** Поле «ветка / main» и чтение файла в начале любой работы с компонентом.

### 3. Нет процедур для 5 повторяющихся задач
- **3A. Скилл на каждую задачу** (гайдлайн, ревью компонента, токены, ревью dev-стенда, ревью Storybook) — с чеклистом и критерием «готово».
- **3B. Один ревью-движок + чеклисты.** Общая механика «источник правды ↔ объект → расхождения» для 4 ревью; различаются только чеклисты и источники (Figma, стенд, Storybook).
- **3C. Отчёт покрытия обязателен.** «Проверено 24 из 24 фреймов, не проверено: …» — чтобы «проверил не всё» было видно сразу.

### 4. Протокол провоцирует объём
- **4A. Стандарт ответа.** Вывод в 1–2 строки → находки таблицей (что → где → что сделать) → вопросы. До ~150 слов, детали по запросу.
- **4B. Убрать служебное.** Блок «Использованные скиллы» — по запросу; tone-of-voice — только для внутренних текстов.
- **4C. Шаблоны вывода скиллов** переписать под стандарт.

### 5. Шум в репо
- **5A. Чистка по аудиту** — попутно, по мере затрагивания файлов.
- **5B. Лёгкий протокол** — меньше обязательной загрузки на старте.

## Развилка: где идёт работа
- **claude.ai Project:** репо только на чтение → память (карточки, status-файлы) писать нельзя, только Claude Docs.
- **Claude Code (эта среда):** читает и пишет репо, читает Figma, коммитит сам.

## Рекомендуемый порядок
1. **4A + 4B** — дёшево, эффект сразу.
2. **1A + 1B** — реестр и токены, основа для всего остального.
3. **2A** — карточка на живом Табеле.
4. **3B + 3C** — ревью-движок, первым — обновление токенов (понятная задача, как Badge).
5. **5A** — попутно.
