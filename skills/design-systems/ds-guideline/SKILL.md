# Гайдлайн компонента

## Когда использовать
- «Напиши гайдлайн для Modal header»
- «Переведи гайдлайн Button из чек-листа в новый формат»
- «Сделай общий гайд для компонента и его сабкомпонентов»

Скилл не покрывает: изменение самого компонента, миграцию токенов (→ `ds-token-update`), решения по API (→ `skills/design-systems`).

## Что делает
Собирает гайдлайн по `templates/component-guideline.md` (структура — `docs/guideline-structure.md`) из фактов компонента в Figma и данных `ds/`. Факты — только из источников; правила использования без источника — `TODO: проверить`. Результат — `ds/guidelines/<компонент>.md`, по просьбе — вёрстка в ветке Figma.

## Контекст и принципы
- **Показывать, а не рассказывать.** Гайд смотрят, а не читают: картинка с разметкой вместо абзаца, пример вместо описания. Длинные таблицы никто не читает.
- **Без воды.** Каждая строка текста сообщает факт, которого не видно на примере. Нечего добавить — строки нет.
- **Один блок — одна тема.** Не смешивать в одной сетке несвязанные свойства; сабкомпонент описывается целиком в своём блоке, а не кусками по разделам.
- **Только реальное.** Примеры «в интерфейсе» — из настоящих макетов продукта. Скелеты, плейсхолдеры и выдуманные экраны запрещены.
- **Факт или предположение — видно всегда** (в markdown и status-файле; на канвасе Figma TODO нет).
- Имена — латиницей как в Figma; токены — полным именем из `ds/tokens.md` со значением; нет токена — «нет токена».
- Flutter-имена и Mantine-пропсы неизвестны → `TODO: мобильщики` / `TODO: фронты`.
- Figma — только чтение, пока пользователь не попросил вёрстку и не назвал ветку.

## Метод
1. **Контекст.** Компонент в `ds/components.md` и `ds/component-props.md`; grep имени по `figma-status/**`, `tasks/`, `ds/decisions.md`. Старый или свободный гайд на странице компонента (даже если в реестре «нет») — источник требований.
2. **Факты из Figma** (`use_figma`, только чтение):
   - **цифры для блока «Коротко»:** число вариантов (`children` набора), значений `Size`, значений главной оси (Align / Style / Type), опций контента (BOOLEAN + SLOT + INSTANCE_SWAP, которые видит дизайнер); при наличии — число сабкомпонентов;
   - слои типичного варианта → «Анатомия»; сабкомпоненты (свои компоненты, вложенные в родителя, которые дизайнер настраивает отдельно) → блок «Сабкомпоненты»; вложенные библиотечные компоненты без своей настройки (Badge, Icon) — только строкой в анатомии;
   - `componentPropertyDefinitions` → «Свойства»: сгруппировать по смыслу (ведущий элемент, заголовок, дополнительный контент, оформление, размер); свойство, которое не действует при другом значении, — «не действует при …»;
   - оси State → «Состояния»; по каждому состоянию сверить вес шрифта, цвета текста и иконок, вариант вложенных компонентов (полный перебор вариантов, не выборка);
   - размеры, паддинги, зазоры, радиусы, текстовые стили по размерам → «Спецификация» (разметкой); токены — проверка по ключам коллекций 🧩 Tokens у привязанных переменных (быстро) или `ds/_scripts/component-token-audit.js` (полно);
   - реальное использование: инстансы компонента вне его страницы (`getInstancesAsync()` у вариантов), фреймы «Примеры использования» на странице компонента → «Когда использовать» и «В интерфейсе»;
   - длинный текст: проверить тестовым инстансом с длинным Title / лейблом (перенос, обрезка, наезд на соседей), а не по настройкам слоя.
3. **Сборка** по шаблону: сначала факты, затем правила; правило без источника → `TODO: проверить`.
4. **Проверка перед выдачей:**
   - имена свойств и значений есть в `ds/component-props.md`, токены — в `ds/tokens.md`, цифры «Коротко» совпадают с Figma;
   - перед финалом перечитать компонент: его могли изменить во время работы;
   - утверждения старого гайда и правки со стороны, которые не подтвердились, — в status-файл («не подтвердилось: …»);
   - при переписывании — число TODO до и после;
   - строка покрытия — в чат и status-файл: «Разделов N из применимых M, на фактах K, TODO: T».
5. **Выдача:** `ds/guidelines/<компонент>.md` + короткий ответ: вывод, до 5 главных вопросов, следующий шаг.
6. **Вёрстка в Figma** — только по просьбе и в названной ветке (правила ниже). Собирает **один агент из блоков Guide kit** (см. «Guide kit»); параллельные команды не использовать — тест на Badge: то же время, ×3,4 токенов (`docs/experiments.md`).
7. **Самопроверка глазами лида** (чек-лист ниже) — до выдачи ссылки.
8. **Фидбек** пользователя → `feedback.md`.

## Вёрстка в Figma

Текст: `_Guide/Caption`, `_Guide/Subheading`. Разметка: `_Guide/Marker` (Number / Letter), `_Guide/Dimension` (Horizontal / Vertical), `_Guide/Overlay` (Padding / Gap, 30%). Таблица: `_Guide/Table row`. Образец значений — гайд Badge `24009:143313`. ID, свойства и приёмы — `ds/_scripts/guide-kit.json`. Сейчас kit лежит в ветке `QbTS4UqcIFOYBGNAzKeD13`, страница «Guidline template» `24184:3729`, фрейм «Guide kit» `24191:271`; после мерджа в `main` Core kit будет в каждой новой ветке. Гайд собирать только из инстансов kit; свои фреймы — лишь ряды внутри слотов. Нет нужного блока — сначала добавить его в kit, потом использовать.

**Сборка:** `_Guide/Frame` → `_Guide/Cover` (Title, превью в Preview) → `_Guide/Section` на каждый раздел (номер сквозной по факту) → блоки в Content. Нет kit в файле — обычный фрейм с теми же значениями (`guideFrameValues` в json).

**Каркас** (значения `_Guide/Frame` и `_Guide/Section`)**.** Фрейм 1600, поля 96, между разделами 160. Раздел — две колонки: слева 320 (номер, заголовок 32/40 Bold, описание 16/24 серое — только если добавляет факт), справа — подложка `bg/neutral/primary`, радиус 24, паддинг 48; плитки примеров внутри — белые. Подписи примеров над ними, 13/18 серые: только `Prop=Value` или 2–4 слова.

**Тексты в примерах** — реалистичные русские, как в продукте (берём из макетов; нет — пишем типичный для интерфейсов случай: «Не удалось сохранить изменения» + «Проверьте подключение к интернету и попробуйте ещё раз»). Заглушки («Title», «Description», «Success!», «Здесь будет текст подсказки», «This is an error message») и тексты из старых гайдов без проверки — запрещены.

**Текст.** На канвасе ≤ 350 слов без ячеек таблиц и текста в инстансах. «Почему» — не больше 3 на гайд и только для неочевидных решений. Запрещено: пересказ заголовка, вводные («ниже показано», «из примеров на странице»), описание того, что видно на примере.

**По разделам:**
- **Обложка** — синяя с превью компонента; под ней «Скопировать себе»: 2–3 готовые конфигурации с подписью сценария.
- **Коротко** (сразу после обложки, требование лида): ряд из 4 белых карточек на серой подложке — число 40/48 Bold + подпись 16 Medium серая: варианты · размеры · главная ось (выравнивания / стили / типы) · опции контента. Склонение по числу («24 варианта», «3 размера», «8 опций контента»).
- **Когда использовать** — `_Guide/When`, `Layout=Tiles` (ревью Zhandos 2026-10-02: «как в Делаем / не делаем»): подложка `bg/neutral/primary` (радиус 24, паддинг 48), две колонки с зазором 24, выравнивание по верху. Колонка: метка один раз — кружок 24 (`bg/success/primary` / `bg/critical/primary`, белая галочка / крестик) + «Используем» / «Не используем» 18/24 Semi Bold `text/success/primary` / `text/critical/primary`; ниже пункты с зазором 24. Пункт (`_Guide/When item stacked`) — **своя** белая плитка `bg/white/white-primary` (радиус 16, высота 180, пример по центру), под ней текст 16/24 Regular `text/neutral/primary` ≤ 7 слов. В «Используем» пример — сам компонент с реальным текстом; в «Не используем» — компонент-замена, текст «случай → компонент». Несколько примеров в одной плитке запрещено. Только настоящие инстансы, без скелетов и `OLD`.
- **Анатомия** — один пример с маркерами + таблица «№ · Элемент · Что это (слой / компонент) · Обязательный · Стиль и токены». Маркер стоит **на элементе** (центр маркера на краю или углу элемента) или соединён с ним линией 1px `border/neutral/primary`; столбец маркеров в стороне от элементов запрещён. Нужен второй пример (часть есть только в другом варианте) — нумерация продолжается, маркеры так же привязаны.
- **Свойства** — подблоки по смыслу (ведущий элемент: Back / Icon; заголовок: Status / Description; доп. контент: Stepper / Media; оформление: Border / Shadow; размеры — линейкой). В подблоке: базовый пример, рядом примеры, где меняется **одно** свойство; одинаковые тексты и ширина, высоты в ряду выровнены. Общая сетка «переключателей» вперемешку запрещена.
- **Состояния** — ряд примеров по существующим состояниям.
- **Поведение и контент** — пары «так / не так» (длинный текст, переполнение, адаптив). Дефекты компонента — только здесь, с подписью «сейчас так».
- **Делаем / не делаем** — `_Guide/DoDont` (пример в слот Example), образец Zhandos `24009:248079` (ветка `QbTS4UqcIFOYBGNAzKeD13`): подложка `bg/neutral/primary` (радиус 24, паддинг 48), пары в ряд с зазором 24, между парами 48. Колонка (вертикально, зазор 16): метка как в «Когда использовать» (кружок 24 + «Делаем» / «Не делаем» 18/24 Semi Bold цветом) → белая плитка `bg/white/white-primary` (радиус 16, высота 180, пример по центру) → правило **под плиткой** 16/24 Regular `text/neutral/primary`, ≤ 8 слов. Пара показывает видимую разницу. Без цветных полос и обводок.
- **В интерфейсе** — только реальный макет: из «Примеров использования» на странице компонента или из продуктового макета **в этом же файле** клонировать **только нужные элементы** (карточки, строку таблицы, шапку) 1× и сложить в auto-layout. Весь экран, обрезанный рамкой с `clipsContent` или со скрытыми слоями, — запрещено: костыльно и утяжеляет файл (ревью дизайнеров 2026-10-02). Экран в другом файле → попросить дизайнера вставить его в ветку и клонировать оттуда (загрузка картинок `upload_assets` из облачной среды не работает — прокси 403). Внутри клона ничего не подменять (в т.ч. `OLD Badge` → `Badge`): это уже не реальный пример. Макет собран на старом компоненте — не брать. Перед клоном проверить, что фрейм не архивный (opacity, имя). Реального примера нет → раздел не выводить, вопрос дизайнеру. Скелеты и выдуманные экраны — запрещены.
- **Спецификация** — разметкой, как анатомия: пример крупнейшего размера на белой плитке; паддинги и зазоры — полупрозрачные заливки поверх (`_Guide/Overlay`: `bg/critical/secondary-light` для паддингов, `bg/brand/secondary-light` для зазоров, 30%), размеры — `_Guide/Dimension`; у каждой меры буквенный маркер A, B, C…; под картинкой таблица по маркерам «Маркер · Что · lg · md · sm» (значение + токен), ≤ 10 строк. Цвета по состояниям — отдельной таблицей ≤ 6 строк, только если меняются. Блока и комментариев про a11y на канвасе нет (решение Zhandos 2026-10-01).
- **Сабкомпоненты** — отдельный раздел после «Спецификации», по подблоку на сабкомпонент: назначение (1 строка) и где он в родителе (маркер из анатомии) → свойства (подблоки по тем же правилам) → состояния → спецификация разметкой. Сабкомпонент без свойств (только State) — назначение, состояния, спецификация. В других разделах сабкомпоненты не расписывать.
- **Flutter** — только для кроссплатформенных / мобильных: таблица «Свойство Figma → виджет / параметр» и отличия от web.
- Нет TODO, оранжевого текста, эмодзи, плашек и комментариев про a11y. Находки по a11y (контраст, фокус, хит-зона) — только в status-файл как открытые вопросы и одной строкой в чат.

**Высота.** Цель — раздел ≤ ~1200. Превышение допустимо в «Свойствах» и «Сабкомпонентах», если каждый подблок отвечает на свой вопрос; иначе — убрать примеры, которые ничего не добавляют.

**Технически:**
- образец визуала — Modal header v2 `23637:1666` (ветка `bRwFkumYDoKh1OQv5a5dYp`); между файлами клонировать нельзя — обложку и раскладку пересобирать по значениям образца (сетка линиями, логотип векторами; noise-заливку API не создаёт);
- ключи переменных и стилей Tokens: `figma.teamLibrary.getAvailableLibraryVariableCollectionsAsync` → `getVariablesInLibraryCollectionAsync` → `importVariableByKeyAsync`;
- `createAutoLayout` даёт белую заливку — сразу `fills = []`; у ячеек и плиток `clipsContent = false` (иначе режет Focus); `resize()` до `layoutSizing*`;
- вызов обрывается через ~60 с — одна подложка за вызов; после таймаута проверить auto-layout (дети на y=0 → переключить `layoutMode`);
- клонировать инстансы только из своей секции; слот искать среди прямых детей (`findOne(SLOT)` находит вложенный);
- мелкие компоненты (Close button) — 1×, не масштабировать (ломает привязки токенов);
- новая секция — справа от соседних с зазором ≥ 400, проверить bounds детей страницы;
- после — скриншоты всего фрейма и разделов, один проход правок; сделанное и вопросы — в `figma-status/<файл>/<компонент>.md`.

## Самопроверка глазами лида
Перед выдачей пройти по каждому пункту по скриншотам:
1. После обложки — 4 карточки «Коротко», цифры сверены с Figma.
2. Нет предложения, которое можно удалить без потери факта.
3. Каждый маркер анатомии однозначно указывает на свой элемент.
4. Сабкомпоненты описаны в одном разделе и нигде больше.
5. Ни в одной сетке не смешаны несвязанные свойства; в каждом примере меняется одно свойство.
6. «Когда использовать» и «Делаем / не делаем» — по образцам Zhandos: метка с кружком сверху, белая плитка, без полос; в паре видна разница.
7. «В интерфейсе» — реальный макет; иначе раздела нет.
8. Спецификация — разметка с маркерами и короткая таблица, а не простыня строк.

## Формат вывода
Файл по `templates/component-guideline.md`. Первая строка: `Источник: Core kit <node> (<ветка>), <дата>. Скилл ds-guideline <версия>.` В чат — только сводка и главные вопросы.

## Анти-паттерны
- Вода: пересказ заголовка, «ниже показано», описание того, что видно.
- Маркеры анатомии столбиком в стороне от элементов.
- Сетка «переключателей», где перемешаны Back, Status, Media и Stepper.
- Сабкомпонент кусками в «Анатомии», «Свойствах» и «Спецификации».
- Скелет или выдуманный экран в «В интерфейсе».
- Спецификация простынёй таблиц вместо разметки.
- Цветные полоски и обводки в «Делаем / не делаем» и «Когда использовать».
- Придуманные правила, свойства или токены; голые числа, когда есть токен.
- Писать в Figma без явной просьбы и ветки.

## Примеры
✅ Подпись примера: «Status=true». ❌ «Пример со статусом рядом с заголовком, показывает состояние объекта».
✅ «В интерфейсе»: клон фрейма «Примеры использования / Приглашение кандидата». ❌ Дровер с серыми плашками вместо полей.
✅ Спецификация: картинка с A–F и таблица из 6 строк. ❌ Три таблицы по 12 строк.
