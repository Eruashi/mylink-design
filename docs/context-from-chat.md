# Контекст из чата (claude.ai, 2026-09-26)

## Проблема
- Каждый новый чат начинается с нуля: нужно заново объяснять процесс, искать и подавать контекст.
- Много времени уходит на перепроверку результата ИИ.
- Ответы Claude перегружены: много текста, тяжело считывать.

## Принципы решения
1. **Память — в файлах.** Status-файл на единицу работы (компонент DS или продуктовая таска). Агент читает его в начале сессии и обновляет в конце.
2. **Процедуры — в скиллах.** Всё повторяющееся оформляется скиллом: шаги, чеклист, формат вывода. Скиллы работают в любом чате, в отличие от project instructions.
3. **Справочники вместо поиска руками.** Реестр компонентов, таксономия токенов, шаблоны.
4. **Самопроверка обязательна.** Каждый скилл, который пишет в Figma, заканчивается дифом «было → стало».
5. **Скиллы улучшаются через фидбек.** Модель не учится между чатами. После каждого реального прогона — запись в `feedback.md`. Раз в несколько прогонов Claude Code предлагает дифф в `SKILL.md`. Для тестовых прогонов — `skill-creator`.

## Формат ответов
Объём и структура — отдельная настройка, не tone of voice. Tone of voice = как звучит. Формат = сколько и как подано.
Правила формата: в `CLAUDE.md`, в Settings → Profile (claude.ai) и в `PROJECT_INSTRUCTIONS.md`.

## Figma — слой исполнения, а не домен
Не добавлять Figma строкой в таблицу триггеров. Любой домен выдаёт результат либо текстом, либо действием в файле.
В `PROJECT_INSTRUCTIONS.md` нужен шаг «Исполнение в Figma»:
- запись в Core kit — только в ветку;
- сначала чтение, потом запись;
- самопроверка дифом;
- обновление status-файла.

## Скиллы: дизайн-система
| Скилл | Что делает |
|---|---|
| `ds-token-update` | Токены в компоненте и новые токены в файле Tokens. Сверка с таксономией. Нет семантического токена — не подставляет примитив молча, а предлагает новый. Диф + запись в ченжлог. |
| `ds-review` | Три режима: компонент / токены / гайдлайн. Включает a11y по реальным переменным. Находки раскладываются на «исправить / отдельная таска / принять». Базы: `design:accessibility-review`, `design:design-system`. |
| `ds-guideline` | Гайдлайн и примеры по шаблону. Анатомия и состояния — из компонента, аналоги — из `design-system-component`. |
| `ds-changelog` | Собирает ченжлог из status-файлов за период. |
| `ds-dev-review` | Ревью компонентов, которые собрали разработчики. Механика общая с тех-ревью дева. |

- Новые компоненты: агент исследует аналоги и предлагает API текстом → Zhandos утверждает → агент собирает каркас (`figma:figma-generate-library`).
- Иллюстрации — отдельный эксперимент: Weave в Figma или SVG по правилам стиля.

## Скиллы: продуктовая работа
| Скилл | Что делает |
|---|---|
| `task-intake` | Таска из Jira → выжимка, открытые вопросы, флоу в FigJam, интерактивный прототип (артефакт), инвентарь скоупа (экраны, состояния, edge cases). Всё в Claude Doc таски. |
| `figma-task-setup` | Дублирует основу из прошлой таски, разворачивает шаблон страницы, раскладывает по секциям. |
| `pre-review` | Режимы: дизайн / продукт / UX writing / «как лид» (по собранным типовым замечаниям лида). Читает секцию прямо из Figma. |
| `handoff-notes` | Гайды для фронтов и примечания из данных макета → секция Notes for dev или аннотации Dev Mode. |
| `dev-tech-review` | Браузер (Chrome DevTools / Playwright): скриншоты состояний + computed styles → сравнение с Figma → список расхождений + черновик комментария фронтам. Логин на стенд делает Zhandos. |

- Инвентарь скоупа закрывает вопрос «что ещё не нарисовал»: агент сверяет чеклист с фреймами в Figma.
- Принятые и отклонённые варианты фиксируются в Claude Doc таски, чтобы агент не предлагал отклонённое повторно.

## Шаблон страницы таски в Figma
Cover (ссылка на Jira, статус) → Brief → Flow → Экраны по сценариям → States и edge cases → Notes for dev → Archive (отклонённые варианты).
Правила неймнинга фреймов и секций — описать в `figma-file-structure.md`.

## Роли инструментов
- **Figma AI Agent** — точечные правки внутри канваса.
- **Claude (claude.ai)** — задачи, где нужно свести несколько источников: Jira, репозиторий, браузер, документы.
- **Claude Code** — работа с репозиторием: скиллы, аудит, фидбек-цикл.
- Все три инструмента работают по одним справочникам из репозитория.

## Где хранится память
- DS: status-файлы в репозитории (`figma-status/`).
- Продуктовые таски: Claude Doc на таску — бриф, решения, инвентарь скоупа. Видят команда и лид.

## Коннекторы
- **Подключены:** Figma, Mobbin, Miro, Gamma, Lucid, Google Drive, Gmail, Google Calendar, Vercel, Claude Docs, браузерные инструменты (Chrome DevTools, Playwright, Claude in Chrome).
- **Нужен:** Jira (Atlassian).
